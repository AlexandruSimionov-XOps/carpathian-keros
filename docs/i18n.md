# Internationalization (RO / EN)

There are two dictionaries, one per runtime:

| File | Used by | Contains |
|---|---|---|
| `static/js/i18n.js` | Browser UI | UI strings (`translations.en/ro`), WMO labels, locale helpers |
| `services/i18n.py` | PDF export | PDF strings (`LABELS`), WMO labels (`WMO_CODES`), weekday names (`WEEKDAYS`) |

> **The WMO labels are duplicated on purpose. Keep both copies identical.** If you change a label in one file, change it in the other in the same commit.

## How the UI is translated

Markup declares what to translate. `applyTranslations()` in `app.js` fills it in:

```html
<h3 data-i18n="hourlyTitle">Next 24 hours</h3>                 <!-- textContent -->
<input data-i18n-placeholder="searchPlaceholder">              <!-- placeholder -->
<button data-i18n-aria="languageToggle">                       <!-- aria-label -->
<span data-i18n="chart.tempAxis">                              <!-- nested key -->
```

The English text inside the HTML is only a placeholder until the script runs.

Dynamic text (conditions, weekdays, numbers, chart labels, error messages) comes from `render()`, which calls:

| Helper | Purpose |
|---|---|
| `CK_I18N.t(lang, "dotted.key", {vars})` | Lookup with `{placeholder}` substitution. Falls back to English, then to the key itself |
| `CK_I18N.wmoLabel(code, lang)` | Weather condition text |
| `CK_I18N.weekday(isoDate, lang, "short" \| "long")` | `Intl` weekday name, capitalised (`Sâm.`, `Thu`) |
| `CK_I18N.shortDate(isoDate, lang)` | `25 nov.` / `Nov 25` |
| `CK_I18N.formatNumber(value, lang, decimals)` | `Intl.NumberFormat` (`1,5` vs `1.5`). Rounds half away from zero (3.5 → 4, −3.5 → −4), uses a true minus sign (−) and never shows `−0` |

Locales: `en → en-US`, `ro → ro-RO`.

## Language state

- `localStorage["ck-lang"]` holds `"en"` or `"ro"`. With nothing saved, or an unknown value, the UI uses **`"ro"`** (`DEFAULT_LANG` in `i18n.js`). The HTML's fallback text is Romanian too, so English never flashes up before the script runs.
- Switching language re-renders **without refetching**. The city, the data and the weather scene stay put; text, charts, day cards and the PDF link are rebuilt.
- `<html lang>` is updated, which also helps screen readers pronounce the text correctly.
- The PDF language is whatever `lang` is on the export URL. The backend accepts only `en` and `ro` and falls back to `en`.

## Keys reference (frontend)

Top level: `tagline, languageToggle, searchPlaceholder ("{count}"), searchPlaceholderShort (phones, via `data-i18n-placeholder-short`), suggestionsLabel, noMatches ("{query}"), countyLabel ("{county}"), capitalLabel, population ("{n}"), searchButton, searchLabel, presetsLabel, currentConditions, feelsLike, humidity, wind, downloadPdf, hourlyTitle, hourlyTitleDay ("{day}"), showNext24h, dayCardLabel ("{day}"), hourlySubtitle, forecastTitle, rangeSubtitle, loading, today, stale, footer`

`errors.*` must have one entry per backend error code, plus `network`, which only exists on the client:
`city_not_found, invalid_city, upstream_error, network`

`chart.*`: `temperature, precipitation, precipChance, range, min, max, hour, tempAxis, precipAxis`

`{count}` in `data-i18n` / `data-i18n-placeholder` text is filled from `<body data-city-count>` (319), so the placeholder stays correct if the list changes.

## Preset city labels

These are defined in `PRESET_CITIES` in `app.py` (in display order) and rendered as `data-label-en` / `data-label-ro` on each chip. Only Bucharest / București differs between the two languages.

City names elsewhere (suggestions, headings, PDF) always use the official Romanian name. County labels are localized: `jud. Cluj` / `Cluj County`.

## Romanian orthography

- Always use **comma-below** `ș ț Ș Ț` (U+0219, U+021B, U+0218, U+021A), never the cedilla forms `ş ţ`. The geocoder sometimes returns cedillas, and `weather_service.py` converts them.
- Use sentence case for labels: "Prognoză pe 7 zile", not "Prognoză Pe 7 Zile".
- Use the formal plural for instructions ("Încercați", "Verificați").

## Adding a new string

1. Add the key to **both** `en` and `ro` in `static/js/i18n.js`. A missing `ro` key falls back to English, which is easy to miss.
2. Reference it with `data-i18n="key"` in the markup, or `t("key")` in `app.js`.
3. If the PDF needs it too, add it to both languages in `LABELS` in `services/i18n.py`.

## Adding a third language (e.g. Hungarian)

1. `static/js/i18n.js`: add a `hu` block to `translations`, `hu` to every `wmo` entry, `hu: "hu-HU"` to `locales`, and `hu` to `unknown`.
2. `services/i18n.py`: add `"hu"` to `SUPPORTED_LANGS`, `hu` to `WMO_CODES`, `WEEKDAYS["hu"]` and `LABELS["hu"]`.
3. Language toggle: the current button flips between two languages (`state.lang === "en" ? "ro" : "en"` in `init()`, plus the two `data-lang-option` spans). Replace it with a three-way control.
4. PDF: `_fmt_num` uses a comma decimal only for `ro`. Extend that check if the new language also uses commas.
5. Region labels: `weather_service.geocode` only builds `en` and `ro` names. Add a `hu` entry.
